# Portfolio Rebalancer (포트폴리오 리밸런서) — Foundational Knowledge

## 역할 정의

포트폴리오 리밸런서는 **목표 자산 배분(target allocation)으로부터의 이탈을 감지하고, 최소 비용으로 목표 비중을 복원**하는 전문 에이전트다. 분석이나 전략 수립을 담당하지 않는다. "BTC 60%, ETH 30%, PM 10%"라는 목표 비중이 주어지면, 현재 포트폴리오의 드리프트를 측정하고, 언제·어떻게 리밸런싱할지 판단하여 실행하는 것이 역할이다.

리밸런싱의 본질: **"높은 것을 팔고 낮은 것을 사는"** 체계적 역발상 메커니즘. 감정 없이 기계적으로 수행하기에 AI 에이전트에 최적화된 작업이다.

## 핵심 개념

### 1. Threshold-based vs Calendar-based Rebalancing

**Calendar-based (정기 리밸런싱)**:
- 고정 주기로 리밸런싱 실행 (월간, 분기, 반기)
- 드리프트 크기와 무관하게 스케줄에 따라 실행

| 주기 | 장점 | 단점 |
|---|---|---|
| 월간 | 빈번한 교정, 드리프트 제한 | 수수료 누적, 불필요한 거래 |
| 분기 | **기관 표준**, 비용/효과 균형 | 급격한 시장 변동에 느린 반응 |
| 반기/연간 | 최소 비용, 세금 최적화 | 큰 드리프트 허용, 리스크 증가 |

**Threshold-based (임계값 리밸런싱)**:
- 드리프트가 설정 임계값 초과 시에만 실행
- 불필요한 거래 최소화, 의미 있는 이탈만 교정

**크립토 최적 임계값 (실증 데이터)**:
- Shrimpy 백테스트 결과: **15% 임계값이 최적** (HODL 대비 +77.1% 중위 수익)
- 기관 크립토 표준: 8-10% 임계값 (보수적)
- 5% 미만: 과도한 거래 → 수수료가 이익 잠식

**Hybrid (하이브리드) — 권장**:
```
매일 포트폴리오 검사 (calendar trigger)
  → 드리프트 > 임계값? (threshold trigger)
    → YES: 리밸런싱 실행
    → NO: 다음 검사까지 대기
```

### 2. 드리프트 측정 방법 (Drift Measurement)

**절대 드리프트 (Absolute Drift)**:
```
드리프트_i = |현재 비중_i - 목표 비중_i|

예시: 목표 BTC=60%, 현재 BTC=68%
  → 드리프트 = |68% - 60%| = 8%p
```

**상대 드리프트 (Relative Drift)**:
```
상대 드리프트_i = |현재 비중_i - 목표 비중_i| / 목표 비중_i × 100

예시: 목표 BTC=60%, 현재 BTC=68%
  → 상대 드리프트 = |68-60| / 60 × 100 = 13.3%
```

**포트폴리오 전체 드리프트**:
```
총 드리프트 = Σ |현재 비중_i - 목표 비중_i| / 2

예시: 목표 (BTC 60%, ETH 30%, SOL 10%)
      현재 (BTC 68%, ETH 25%, SOL 7%)
  → 총 드리프트 = (|8| + |5| + |3|) / 2 = 8%p
```

**어떤 드리프트 지표를 사용할 것인가?**:
- **절대 드리프트**: 대형 포지션에 적합 (BTC 60%→68%는 8%p, 의미 있음)
- **상대 드리프트**: 소형 포지션에 적합 (SOL 5%→8%는 3%p지만 상대적으로 60% 증가)
- **권장**: 둘 다 추적. 절대 15%p 또는 상대 25% 중 하나라도 초과 시 트리거

### 3. Band Rebalancing (밴드 리밸런싱)

각 자산에 허용 밴드(tolerance band)를 설정:

```
목표: BTC 60%
밴드: ±5%p (절대) → 허용 범위: 55% ~ 65%
→ BTC가 55-65% 사이면 아무것도 하지 않음
→ 벗어나면 목표(60%)로 복원
```

**밴드 크기 결정 요인**:

| 요인 | 좁은 밴드 (3-5%) | 넓은 밴드 (10-15%) |
|---|---|---|
| 거래 빈도 | 높음 (주간~일간) | 낮음 (월간~분기) |
| 수수료 영향 | 큼 | 작음 |
| 리스크 통제 | 엄격 | 유연 |
| 적합 시장 | 저변동 | **고변동 (크립토)** |

**크립토 포트폴리오 권장 밴드**:

| 자산 유형 | 절대 밴드 | 상대 밴드 |
|---|---|---|
| BTC (60% 목표) | ±8%p | ±13% |
| ETH (25% 목표) | ±5%p | ±20% |
| 알트코인 (10% 목표) | ±4%p | ±40% |
| PM 포지션 (5% 목표) | ±3%p | ±60% |

### 4. 거래 비용 손익분기점 (Transaction Cost Break-Even)

리밸런싱은 비용이 든다. 비용보다 기대 이익이 커야 실행 가치가 있다.

**비용 구성**:
```
총 비용 = 거래 수수료 + 슬리피지 + (스프레드 비용) + (가스비, PM의 경우)
```

**손익분기 공식**:
```
리밸런싱 기대 이익 = 드리프트² × 상관계수 보정 × 변동성 / 2
리밸런싱 비용 = 이동 금액 × (수수료율 + 슬리피지율)

실행 조건: 기대 이익 > 비용 × 안전 계수(1.5)
```

**실전 간편 판단**:
```
Binance Spot (수수료 0.075%):
  최소 이동 금액 $200 이상이면 일반적으로 비용 효율적
  $50 미만 이동: 수수료 비중 과다, 스킵

Polymarket (가스 + 스프레드):
  최소 이동 금액 $100 이상
  $30 미만: 가스 비용이 이익 잠식

크로스 플랫폼 (Binance → PM):
  USDC.e 스왑 비용 + 가스 고려
  최소 이동 금액 $200 이상
```

### 5. Partial Rebalancing (부분 리밸런싱)

**완전 리밸런싱 (Full Rebalancing)**:
- 모든 자산을 정확히 목표 비중으로 복원
- 비용 높음, 불필요한 소규모 거래 다수 발생

**부분 리밸런싱 — 권장 방식**:
- 가장 크게 이탈한 자산만 교정
- 또는 이탈 자산을 목표까지가 아니라 밴드 경계까지만 복원

```
전략 1: Top-N 이탈 자산만 리밸런싱
  - 절대 드리프트 기준 상위 2-3개 자산만 교정
  - 소규모 드리프트는 무시

전략 2: 밴드 경계 복원 (Bring-to-Band)
  - 밴드 밖 자산을 밴드 경계까지만 이동 (목표까지 X)
  - 거래량 최소화

전략 3: 캐시 플로우 리밸런싱
  - 신규 입금(DCA 등)을 비중 부족 자산에 우선 배분
  - 매도 없이 리밸런싱 효과 달성
  - **세금/수수료 최소 → 최우선 전략**
```

### 6. 크로스 플랫폼 리밸런싱 (Binance + Polymarket)

**고유한 도전 과제**:
```
Binance 자산: BTC, ETH, SOL (크립토)
Polymarket 자산: 예측 마켓 포지션 (바이너리 토큰)
현금: USDT(Binance) + USDC.e(PM)
```

**자산 간 이동 경로**:
```
Binance → Polymarket:
  1. Binance에서 USDC 출금 (Polygon 네트워크)
  2. Paraswap에서 Native USDC → USDC.e 스왑 ($50 청크)
  3. USDC.e를 Proxy Wallet 전송
  4. PM에서 포지션 매수
  소요 시간: 10-30분, 비용: ~$0.10-$0.50

Polymarket → Binance:
  1. PM 포지션 매도 (USDC.e 수령)
  2. USDC.e → Native USDC 스왑 (Paraswap)
  3. Binance로 USDC 입금 (Polygon)
  소요 시간: 10-30분, 비용: ~$0.10-$0.50
```

**크로스 플랫폼 리밸런싱 우선순위**:
1. 같은 플랫폼 내 리밸런싱 우선 (비용 최소)
2. 신규 입금으로 크로스 플랫폼 불균형 해소
3. 마지막 수단: 자산 이동 (USDC 경유)

## 베스트 프랙티스

### 리밸런싱 실행 체크리스트

1. **포트폴리오 스냅샷 취득**
   - Binance: 전체 잔고 조회 (Spot + Futures)
   - Polymarket: 전체 포지션 가치 조회 (현재 시장가 기준)
   - 현금: USDT + USDC.e 합산

2. **드리프트 계산**
   - 각 자산 현재 비중 vs 목표 비중
   - 절대 + 상대 드리프트 산출

3. **리밸런싱 필요 여부 판단**
   - 임계값 초과 자산 존재?
   - 거래 비용 손익분기 충족?

4. **거래 계획 수립**
   - 매도 자산 / 매수 자산 결정
   - 거래 순서 최적화 (매도 먼저 → 매수)
   - 최소 거래 단위 확인

5. **실행 및 검증**
   - 거래 실행 (Executor 에이전트에 위임)
   - 체결 확인 후 재계산

### 리밸런싱 순서 최적화

```
Step 1: 매도 대상 결정 (비중 초과 자산)
Step 2: 매수 대상 결정 (비중 부족 자산)
Step 3: 매도 먼저 실행 (현금 확보)
Step 4: 매수 실행 (확보된 현금 사용)

왜 매도 먼저?
  → 매수 자금 부족 방지
  → 부분 체결 시에도 매수 가능 금액 명확
```

### Priority-based Rebalancing (우선순위 기반)

모든 이탈을 동시에 교정하지 않는다. 우선순위를 따른다:

```
우선순위 1 (즉시): 절대 드리프트 > 15%p 또는 상대 드리프트 > 30%
  → 리스크 집중. 즉시 교정

우선순위 2 (다음 주기): 절대 드리프트 10-15%p
  → 의미 있는 이탈. 다음 정기 검사 시 교정

우선순위 3 (관찰): 절대 드리프트 5-10%p
  → 밴드 내. 캐시 플로우 리밸런싱으로 점진 교정

우선순위 4 (무시): 절대 드리프트 < 5%p
  → 정상 범위. 거래 비용 대비 이익 없음
```

### 변동성 높은 시장에서의 리밸런싱

크립토 시장에서는 하루에 10-20% 변동이 발생할 수 있다:

1. **급등/급락 직후 즉시 리밸런싱 금지**: 오버슈팅 후 반등/반락 가능
   - 최소 4-6시간 안정화 대기
   - 급변 후 24시간 내 드리프트 재확인

2. **연쇄 청산(Liquidation Cascade) 감지 시**:
   - Funding rate 급등 + 가격 급락 = 청산 캐스케이드
   - 완전 안정화 후 리밸런싱 (보통 24-48시간)

3. **밴드 2배 초과 드리프트**:
   - 정상 밴드의 2배 이상 이탈: 구조적 변화 가능
   - 목표 비중 자체를 재검토해야 할 수 있음 (전략가에 에스컬레이션)

## 주의사항 / 안티패턴

### 절대 하지 말 것

1. **과도한 리밸런싱 (Overtrading)**: 1% 드리프트에 리밸런싱 = 수수료로 수익 잠식. 최소 5%p 임계값 유지
2. **시장 타이밍 시도**: "BTC 더 오를 것 같으니 리밸런싱 지연" → 리밸런서의 역할이 아님. 기계적 실행
3. **전량 리밸런싱 습관**: 항상 목표 비중 100% 복원 시도 → 부분 리밸런싱이 비용 효율적
4. **크로스 플랫폼 이동 남발**: Binance↔PM 간 자금 이동 비용($0.50+) × 빈번 = 상당한 누적 비용
5. **정산 임박 PM 포지션 매도**: 정산일 48시간 내 PM 포지션은 리밸런싱 대상에서 제외 (정산 이익 보존)
6. **손실 확정 회피 편향**: 손실 중인 자산 매도가 필요한데 "기다리면 복구될 것"이라며 지연 → 리밸런싱 원칙 위반

### 흔한 실수

- **목표 비중 미갱신**: 시장 환경 변화(bull→bear) 시 목표 자체가 바뀌어야 하는데 고정
- **가스비 미포함 비용 계산**: PM 리밸런싱 시 Polygon 가스비 빠뜨리면 실제 비용 과소 추정
- **Futures 포지션 미반영**: Binance Futures 포지션을 포트폴리오에 포함하지 않으면 실제 익스포저 왜곡
- **스테이블코인을 자산으로 미처리**: USDT/USDC.e 현금 비중도 목표에 포함해야 함
- **PM 포지션 가치를 매입가로 계산**: 현재 시장가 기준이어야 함 (미실현 손익 반영)

## 판단 기준

### 리밸런싱 트리거 판단 플로우

```
일일 포트폴리오 스캔
  → 절대 드리프트 > 15%p OR 상대 드리프트 > 30%?
    → YES: 즉시 리밸런싱 (긴급)
    → NO: 절대 드리프트 > 8%p?
      → YES: 비용 손익분기 충족?
        → YES: 리밸런싱 실행
        → NO: 다음 검사까지 대기
      → NO: 드리프트 기록, 캐시 플로우로 점진 교정
```

### 최소 거래 단위 기준

| 플랫폼 | 최소 주문 | 권장 최소 | 근거 |
|---|---|---|---|
| Binance Spot (BTC) | ~$5 | $50 | 수수료 대비 의미 있는 크기 |
| Binance Spot (알트) | ~$10 | $30 | Lot size 제약 |
| Polymarket | $1 | $50 | 가스비 + 스프레드 비용 |
| 크로스 플랫폼 이동 | N/A | $200 | 스왑 + 전송 비용 |

### 리밸런싱 비용 추정표

| 시나리오 | 예상 비용 | 비용률 (on $1,000) |
|---|---|---|
| Binance 내 스왑 | 수수료 0.075% | $0.75 |
| PM 내 매도+매수 | 스프레드 1-3% + 가스 | $10-$30 |

| PM → Binance 이동 | 매도 + 스왑 + 입금 | $10-$30 + $0.50 |

|---|---|---|
| < 3%p | 정상 (GREEN) | 모니터링만 |
| 3-8%p | 주의 (YELLOW) | 캐시 플로우로 점진 교정 |
| 8-15%p | 경고 (ORANGE) | 다음 정기 검사 시 리밸런싱 |
| 15%p+ | 긴급 (RED) | 즉시 리밸런싱 |
